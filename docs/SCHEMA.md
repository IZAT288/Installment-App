# Database schema v1

This is the complete target entity schema. Setup creates headers, not every associated service. UUIDs are immutable internal keys. All tables share `uuid` (UUID string, primary key), `id` (unique human-readable string), `createdAt`/`updatedAt` (UTC ISO timestamp), `createdBy`/`updatedBy` (actor email), and `status` (entity lifecycle string). Customer CNIC, phones, IDs and dates are stored as text. Money fields ending in Minor are safe integer paisa; markupBps is integer basis points. All fields default to text unless specified below. Optional fields remain empty; services must validate required fields before writing.

## Types and relationships

- `*Uuid` columns reference immutable `uuid` fields, never worksheet row numbers. customerUuid → Customers; productUuid → Products; contractUuid/amendmentOf → Contracts; paymentUuid → Payments; scheduleUuid → InstallmentSchedules; journalUuid → FinancialJournal; supplierUuid → a future supplier entity (must remain empty until its schema migration). Guarantor references are a JSON array of Guarantors UUIDs. receiverUuid/authorizedBy → Users UUID, while common createdBy/updatedBy and Audit actorEmail store verified email identity. reversalOf → StockMovements UUID. EntityUuid is polymorphic and requires entityType validation.
- `*Json`: serialized JSON string validated against its versioned service schema. `*At`: UTC ISO timestamp; `*Date` and dueDate: YYYY-MM-DD civil date in Asia/Karachi. `*FileId`/driveFolderId: private Drive resource identifier, not public URL.
- Integer fields: quantity, delta, minimumStock, number, installmentCount, version, schemaVersion, nextValue, validRows, invalidRows and all `*Minor`/markupBps fields. Reject unsafe integers. active/stockTracked are booleans.
- Enums: roles SUPER_ADMIN/ADMIN/STAFF; contract status Draft/Pending Approval/Active/Completed/Cancelled/Under Review; schedule status Upcoming/Due Today/Partially Paid/Overdue/Paid (derived); payment methods Cash/Bank Transfer/Easypaisa/JazzCash/Cheque/Other; commitState PREPARED/COMMITTED/REVERSED/RECOVERY_REQUIRED.
- Unique constraints to enforce under lock: business IDs, Users email, Customers CNIC, Products SKU, payment and journal idempotencyKey plus payload digest, (contractUuid, installment number), Settings key, SchemaVersions version.
- Price and branding/terms snapshots remain immutable on activation. paidMinor is a derived cache and must reconcile to allocations and reversal events. Financial events are never physically deleted.
- Repository checks exact headers before every operation; schema changes require an explicit versioned migration. Current foundation implements create/read/health only, with updates, archive and transaction/recovery reserved for later phases.
